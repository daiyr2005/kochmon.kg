# Kochmon AI — frontend (React + TypeScript + Vite)

## Запуск

```bash
npm install
cp .env.example .env     # затем при необходимости поправьте значения
npm run dev              # http://localhost:5173, запросы /api идут на http://localhost:8000
npm run build            # проверка типов и сборка в dist/
```

Без backend можно посмотреть дизайн на демонстрационных данных: в `.env` поставьте `VITE_DEMO=true`.
Демо-данные лежат только в `src/demo.ts` и в рабочем режиме не используются.
С `VITE_DEMO=true` экраны совпадают с утверждённым макетом `kochmon.html` (две сохранённые карточки, баннер «Иссык-Куль Резорт», колесо, AI-чат).

Папка `dist/` собрана заново под текущий код. После любых правок пересоберите её командой `npm run build`.

## Переменные окружения

| Переменная | Значение |
|---|---|
| `VITE_API_URL` | адрес backend, по умолчанию `/api` |
| `VITE_DEMO` | `true` — демонстрационные данные вместо backend |
| `VITE_AI_IMAGES` | `true` — включить кнопку фото в AI, когда backend умеет разбирать изображения |
| `VITE_IMAGE_SEARCH` | `true` — включить поиск по фото |

Секретов во frontend нет и быть не должно. Токен хранится только в памяти страницы.

## Структура

```
src/
  api.ts            все запросы к backend (маршруты из вашего списка), ApiError, режим демо
  types.ts          типы Item, Session, Filters, View
  demo.ts           демо-данные (только VITE_DEMO=true)
  App.tsx           состояние, навигация, окна
  toast.tsx         уведомления
  hooks/useSpeech.ts  голосовой ввод (распознавание речи браузера)
  components/
    AuthScreen.tsx  вход, регистрация, Google, гость
    Find.tsx        главная: поиск, категории, фильтры, список
    Cards.tsx       карточка, рекламный баннер, страница объекта
    Sheets.tsx      фильтры, колесо стран, AI-помощник, подтверждения
    Account.tsx     сохранённое, профиль, мои объявления, добавить объявление, реклама
  styles.css        стили согласованного дизайна (тот же CSS, что в kochmon.html)
  extra.css         дополнения для реальных данных (загрузка, ошибки, пустые списки)
```

## Что подключено к backend, а что нет

Подключено через `src/api.ts` (схемы ответов нужно сверить с реальным FastAPI, места отмечены комментариями):
вход и регистрация, `/users/me`, объявления (список, «мои» через `?mine=true`, создание, архив, удаление),
избранное, `/ai/chat`, каналы Telegram и WhatsApp, рекламные заявки и баннер, Google через `/auth/google`.

Пока недоступно на backend (в интерфейсе честно показывается ошибка или «скоро»):
- поиск в интернете (`searchWeb`), `/search/` ищет только по локальным объявлениям;
- загрузка фото объявлений, фото в AI, поиск по фото;
- восстановление пароля, выход и обновление токена;
- сохранение языка и переключателей уведомлений;
- бронирование и доступность номеров;
- тарифы и оплата (`/plans`, `/subscriptions`, `/payments`): экранов нет.

## Что проверить в первую очередь

1. Формат входа: `POST /auth/login` принимает JSON или форму OAuth2 и что возвращает.
2. Названия полей в `toItem` (`src/api.ts`) под реальную схему `ListingOut`.
3. Как backend возвращает токен после Google (код ожидает `#access_token=...` во фрагменте адреса).
4. Что `DELETE` объявления и `dev-pay` доступны только владельцу и не доступны в production.
